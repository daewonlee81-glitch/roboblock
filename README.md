# 로보블록 (RoboBlock)

RoboMakers 로봇 코딩 플랫폼.

ESP32 로봇을 블록으로 코딩하는 교육용 웹 에디터입니다. 블록을 실행하면 ESP32의 어떤 선(PWM·HIGH/LOW·펄스·I²C·아날로그)에 신호가 나가는지 배선도에서 바로 보입니다.

- **지원 로봇:** 축구로봇(4WD 스키드), 미들봇(메카넘 + EEZYbotARM 흡착), 스모
- **보드:** NodeMCU-32S (ESP32-WROOM-32, 38핀)
- **조종기:** Xbox 무선 컨트롤러 (Bluepad32)

## 기능 (프로토타입 v6)

- 레벨 1~3: 아이콘 블록 → 일반 블록 → C++ 코드 보기 (Blockly 11.2.1)
- ESP32 배선도: ESP32 → 드라이버 모듈(DRV8871, A4988, PCA9685, XY-MOS) → 모터·서보·펌프·밸브, 그리고 전원 배선
- 신호 보기: 실행 중 활성화된 선이 빛나고, PWM은 흐르는 점선, 모터 아이콘은 회전 방향대로 돈다
- 장치 추가와 핀 지정: DC·엔코더·스테핑·서보 모터, 센서 9종, PCA9685 채널 서보. 플래시 핀·입력 전용·ADC2·스트래핑 핀, I²C 주소 충돌, PWM 채널 수를 바로 검사한다
- 실시간 모니터: 장치마다 현재 값과 최근 6초 그래프. 센서는 가상 입력 슬라이더로 시험한다
- 모터 핀과 바퀴 패널: 모터마다 IN1·IN2 핀과 바퀴 위치(예: GPIO 32·33 → 앞-왼쪽)를 정하고, 그 바퀴만 정한 시간 전진·후진해 본다. 로봇과 연결되면 "로봇에 핀 적용·저장"으로 로봇에 보낸다. "[앞-왼쪽] 바퀴만 전진 60% 1초" 블록도 있다
- 창 크기 조절: 블록 창과 오른쪽 창 사이 막대를 끌어 넓이를 바꾼다(폰에서는 높이). 두 번 누르면 원래대로
- 실행을 누르면 배선도가 "전체 보기"로 바뀌어 모든 선이 한눈에 보인다. "확대 보기"는 글자를 크게 하고 옆으로 밀어 본다
- 키보드 이벤트: "⌨ [↑] 키를 누르면", "⌨ [↑] 키를 떼면", "⌨ [↑] 키가 눌렸나?" 블록. 화살표·스페이스·엔터·A~Z·0~9. 로봇과 연결되어 있으면 키보드로 로봇을 몬다
- 가상 Xbox 컨트롤러: 각 로봇 펌웨어와 같은 조작 배치. 보기 + 메뉴를 함께 누르면 비상 정지

## 실제 로봇 연결 (축구로봇, Web Bluetooth)

로봇과 Xbox 컨트롤러를 **동시에 쓰지 않습니다.**

- **조종 모드** (기본): 지금처럼 Xbox 컨트롤러로 조종합니다.
- **블록 모드**: 에디터가 블루투스로 연결되면 로봇이 Xbox 컨트롤러를 끊고 블록으로만 움직입니다. 에디터에서 연결을 끊으면 조종 모드로 돌아가 컨트롤러를 다시 받습니다.
- 블록 모드에서 0.5초 동안 명령이 없으면(탭 닫힘, 전파 끊김) 로봇이 스스로 제동합니다.
- 블록 모드에서 BOOT 버튼을 짧게 누르면 "로봇 버튼을 누르면" 블록이 실행됩니다. 3초 누르면 지금처럼 페어링 초기화입니다.

### 1. 펌웨어 올리기

1. Arduino IDE에 **esp32_bluepad32** 보드 패키지를 설치합니다 (보드 URL은 `firmware/soccer_roboblock/soccer_roboblock.ino` 맨 위 주석 참고).
2. 라이브러리 관리자에서 **Adafruit SSD1306**(Adafruit GFX 포함)을 설치합니다.
3. `firmware/soccer_roboblock` 폴더를 열고 보드 **NodeMCU-32S**로 업로드합니다.
4. 시리얼 모니터(115200)에 `로보블록 웹 블루투스 이름: RoboBlock-XXXX`가 나오면 준비 끝입니다.

기존 `xbox_4wd_robot_new.ino`의 조종 방법, 페어링(MAC 저장, BOOT 3초 초기화), OLED 표시는 그대로입니다.

### 2. 에디터에서 연결

1. 크롬이나 엣지에서 에디터를 엽니다 (윈도우·맥·크롬북·안드로이드). 아이패드·아이폰 사파리는 Web Bluetooth를 지원하지 않습니다.
2. **로봇 연결** → 목록에서 `RoboBlock-XXXX` 선택 → 연결.
3. 연결되면 배선도와 모니터의 모터 값이 로봇이 보낸 실제 출력으로 바뀝니다.

맥에서는 처음에 크롬의 블루투스 권한을 허용해야 합니다 (시스템 설정 → 개인정보 보호 및 보안 → 블루투스).

### 스모 센서 (프로토타입): Sharp 거리 3개 + 바닥 IR 2개

| 센서 | 선 | ESP32 |
|---|---|---|
| Sharp GP2Y0A21 앞 | Vo | **SVP** (GPIO 36) |
| Sharp GP2Y0A21 왼쪽 | Vo | **SVN** (GPIO 39) |
| Sharp GP2Y0A21 오른쪽 | Vo | **GPIO 34** |
| Sharp 3개 공통 | Vcc / GND | **5V** / **공통 GND**, 센서마다 Vcc·GND 사이 10~100 µF. 확장 보드 G·V·S 핀의 V는 점퍼 전압(3.3 V일 수 있음)이라 Vcc는 보드의 5V 핀에 따로 |
| 바닥 IR HW-870 왼쪽 | DO | **GPIO 18** |
| 바닥 IR HW-870 오른쪽 | DO | **GPIO 19** |
| HW-870 2개 공통 | VCC / GND | **3.3 V** (확장 보드 V, 점퍼 3.3) / **G**, AO는 비워 둠 |
| (선택) TCS34725 바닥 색 왼쪽 | SDA / SCL | **16 / 17** (OLED와 같은 I²C) |
| (선택) TCS34725 바닥 색 오른쪽 | SDA / SCL | **13 / 14** (두 번째 I²C) |
| (선택) TCS34725 공통 | VIN / GND | **3V3** / **GND** (LED 핀은 비워 두면 켜짐) |

- 블루투스를 쓰는 동안 ADC2 핀은 읽을 수 없어 거리 센서는 32~39번만 됩니다.
- HW-870은 흰 바닥에서 DO = LOW, 아래 LED가 켜집니다. 파란 가변저항으로 흰 테두리에서 켜지고 검은 바닥에서 꺼지게 맞춥니다. VCC를 5 V로 주면 DO도 5 V라 3.3 V로 줍니다.
- TCS34725는 주소가 0x29로 고정이라 왼쪽·오른쪽을 다른 I²C 선에 답니다.
- 에디터의 "센서 확인"에서 세 거리와 두 바닥 색이 실시간으로 보이고, 거리 센서마다(빈 공간·20 cm)와 색 센서(흰색·검정) 보정을 로봇에 저장합니다.
- 시리얼 모니터(115200)에 0.5초마다 `Sharp  F(GPIO36) 1.00V 30cm  L(GPIO39) ...`가 찍힙니다.
- OLED 오른쪽 아래 두 글자가 바닥 왼쪽·오른쪽입니다 (W 흰색, K 검정, 색 센서면 R 빨강 Y 노랑 G 초록 B 파랑, - 없음).

### 상대 감지 센서 (선택: Sharp GP2Y0D02YK0F ×3)

(선택) 80 cm 안에 물체가 있으면 출력이 HIGH가 되는 디지털 센서입니다. 기본은 꺼져 있고, 에디터에 장치를 넣고 "로봇에 핀 적용·저장"을 누르면 켜집니다. 앞 왼쪽·가운데·오른쪽에 하나씩 답니다. 커넥터는 GP2Y0A21과 같은 3핀입니다.

| 센서 선 | 연결 |
|---|---|
| Vcc | ESP32 **5V** (센서마다 Vcc·GND 사이 10 µF) |
| GND | **공통 GND** |
| Vo | **레벨 변환기(BSS138)** HV1·2·3 → LV1·2·3 → **GPIO 18 · 19 · 23** (왼쪽 · 가운데 · 오른쪽) |

센서 출력은 감지될 때 약 5 V라 ESP32 핀에 바로 꽂으면 안 됩니다. 레벨 변환기는 HV → 5V, LV → 3V3, GND → GND. 레벨 변환기가 없으면 분압 저항(Vo ─ 10 kΩ ─ GPIO ─ 20 kΩ ─ GND)도 되지만, 감지 때 GPIO 전압이 2.5 V를 넘는지 재 보세요. OLED 오른쪽 위의 세 칸이 왼쪽·가운데·오른쪽 감지를 보여 주고, 에디터의 "센서 확인" 칸에 실시간으로 켜집니다.

### 통신 형식

| | UUID | 내용 |
|---|---|---|
| 서비스 | `7b1c0000-5a3e-4c2b-9f6d-2b7e0d1a0c00` | |
| 명령 (쓰기) | `7b1c0001-…` | `01 FL FR BL BR` 바퀴 출력(int8 %, 0=제동) · `02` 제동 · `03` 살아 있음 · `04 글자` OLED · `05 핀 값` 디지털 출력 · `06 바퀴 값` 바퀴 하나 · `07 핀×8` 바퀴 핀 설정(FL·FR·BL·BR 순서 IN1 IN2, 로봇 NVS에 저장) · `08 핀 [핀 핀]` Sharp 핀(앞 [왼쪽 오른쪽]) · `09 단계 [센서]` Sharp 보정 · `0C 핀 핀` 바닥 IR 핀(왼쪽 오른쪽) · `0B 단계` 바닥 색 보정(1 흰색, 2 검정, 0 지우기) · `0A 핀×3 극성` 상대 감지 핀(왼·가운데·오른, 255=안 씀, 극성 1=감지 때 HIGH) |
| 상태 (알림 10 Hz) | `7b1c0002-…` | `A1 모드 플래그 FL FR BL BR 제동비트 순번(2) millis(4) Sharp mV(2) Sharp cm(1) 상대 감지·바닥 IR(1)` (cm: 0=없음, 255=80 cm 넘음 · 상대 감지 bit0 왼 bit1 가운데 bit2 오른, 바닥 IR 흰색 bit4 왼 bit5 오른). 같은 특성으로 `A2 있음 [왼쪽 밝기 색 R G B 보정] [오른쪽 …] 왼쪽Sharp mV(2) cm 오른쪽Sharp mV(2) cm`도 10 Hz로 옴 (색: 0 없음 1 검정 2 흰색 3 빨강 4 노랑 5 초록 6 파랑) |
| 정보 (읽기) | `7b1c0003-…` | `robot=soccer;fw=…;FL=32,33;FR=27,4;BL=25,26;BR=22,21;oled=16,17;boot=0;sharp=36;scal=…;scap=…;sharpL=39;…;sharpR=34;…;opp=255,255,255;opph=1;col=16,17,13,14;colok=1,1;flr=18,19` |

펌웨어는 `soccer_roboblock.ino` 한 파일로 완결됩니다. GATT 표를 바꾸면 `roboblock.gatt`를 BTstack의 `tool/compile_gatt.py`로 다시 만들어 .ino 안의 GATT 표 부분을 바꿉니다.

이 단계에서 블록은 브라우저에서 실행되고 바퀴 명령만 로봇에 보냅니다. 로봇에 프로그램을 저장해 케이블·연결 없이 도는 바이트코드 인터프리터는 다음 단계입니다. "앞으로 2칸", "90° 돌기"는 시간으로 움직이므로 로봇마다 보정이 필요합니다.

## 실행

빌드가 필요 없는 단일 HTML 파일입니다.

```bash
# 로컬에서
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 열기
```

Blockly와 글꼴은 CDN(jsdelivr, Google Fonts)에서 불러오므로 인터넷 연결이 필요합니다.

## GitHub Pages로 서비스하기

1. 저장소 **Settings → Pages**
2. **Source: Deploy from a branch**, **Branch: main / (root)** 선택 후 저장
3. 1~2분 뒤 `https://<아이디>.github.io/roboblock/` 에서 열린다

Pages는 https로 서비스되므로, 나중에 크롬·엣지·안드로이드에서 Web Bluetooth로 로봇에 바로 연결할 수 있습니다.

## 파일

| 파일 | 내용 |
|---|---|
| `index.html` | 에디터 전체 (HTML·CSS·JS 한 파일) |
| `firmware/soccer_roboblock/` | 축구로봇 펌웨어 (Xbox 조종 + 로보블록 블루투스), `.ino` 한 파일 |
| `.nojekyll` | GitHub Pages가 파일을 그대로 서비스하게 함 |

학생이 만든 블록과 장치 구성은 각자의 브라우저(localStorage)에만 저장됩니다.
